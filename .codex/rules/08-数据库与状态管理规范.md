# 数据库与状态管理规范

## 适用范围
适用于本地素材库文件、图片存储、数据 schema、Zustand store、持久化写入和数据迁移。

## 规则条目

### R1: 素材库元数据只能使用 library.json 作为主存储
**断言**：素材库元数据必须保存为应用数据目录内的 `library.json`；不得使用 SQLite、IndexedDB、LocalStorage、远程数据库或浏览器缓存作为素材库主存储。
**示例**：
```json
{
  "schemaVersion": 1,
  "items": []
}
```
**违规特征**：新增 `db.sqlite`、`indexedDB.open("library")`、`localStorage.setItem("library", ...)` 或远程保存素材数据。

### R1.1: 账号数据允许独立落盘 account.json，敏感字段必须加密
**断言**：0.3.x 起账号登录为已批准功能（见 `docs/项目功能全景与账号登录改造指南.md`）。登录态与用户信息（uid、用户名、头像、渠道、token 等）允许在数据目录内另存 `account.json`：非敏感字段明文 JSON，token / 密码等敏感字段必须用 Electron `safeStorage` 加密后以 base64 落盘（参考 `electron/main/ai/aiSettingsStore.ts`、`electron/main/library/promptAccountCrypto.ts`），解密只在主进程内存中进行，绝不落盘明文、不打印日志。不得写入 LocalStorage、IndexedDB 或浏览器缓存；素材库主存储仍只能是 `library.json`。
**示例**：
```text
data\library\account.json   # 非敏感字段明文 + 敏感字段为 safeStorage 加密后的 base64
```
**违规特征**：把 token / 密码明文写入 `account.json`；渲染层把登录态写进 `localStorage`；账号数据混入 `library.json` 的 items 或作为素材库主存储。

### R2: library.json schema 必须固定
**断言**：`library.json` 的顶层字段必须为 `schemaVersion`、`items`、`updatedAt`；每个 item 必须包含 `id`、`title`、`imageFileName`、`prompt`、`negativePrompt`、`tags`、`createdAt`、`updatedAt`。
**示例**：
```ts
export type LibraryFile = {
  schemaVersion: 1;
  updatedAt: string;
  items: LibraryItem[];
};

export type LibraryItem = {
  id: string;
  title: string;
  imageFileName: string;
  prompt: string;
  negativePrompt: string;
  tags: string[];
  createdAt: string;
  updatedAt: string;
};
```
**违规特征**：某些 item 使用 `imagePath`，另一些使用 `file`；或缺失 `schemaVersion` 导致无法迁移。

### R2.1: library.json 必须原子写入并保留滚动备份
**断言**：`writeLibraryFile` 必须通过临时文件写入后再替换正式 `library.json`；每次成功覆盖前保留滚动备份 `library.json.bak`、`library.json.bak.1`、`library.json.bak.2`（共 3 份，最新在 `.bak`）。读取时若主文件缺失、为空或 JSON 损坏，必须按备份槽从新到旧尝试恢复并写回主文件。Windows 上替换已存在目标时必须处理 `rename` 无法覆盖与瞬时 `EPERM/EACCES/EBUSY`。实现见 `electron/main/library/libraryJsonPersistence.ts`。
**示例**：
```text
data\library\library.json
data\library\library.json.bak
data\library\library.json.bak.1
data\library\library.json.bak.2
```
**违规特征**：直接 `writeFile(library.json)` 覆盖；无备份；主文件损坏后启动直接崩溃且不尝试 `.bak`。

### R3: 正式包数据跟随软件目录，托管图片与外链索引严格分开
**断言**：
1. **正式安装版**：`userData`、素材库、设置必须位于**安装目录**下的 `data\`（例如 `D:\Apps\SuYan\data\`）。仅当用户把软件安装在 C 盘时，数据才会落在 C 盘安装路径内；**不得**默认写入 `%APPDATA%\SuYan`。
2. **便携版 / 免安装目录版**：数据必须只放在便携版所在目录下的 `data\`（优先 `PORTABLE_EXECUTABLE_DIR\data`），**不得**写入 C 盘 AppData 或系统临时解压目录。
3. **开发 / 本地打包迭代**：`electron .` 与 `release\win-unpacked\素言.exe` 共用工作区 `release\win-unpacked\data`（用户日常打开的便携目录）。**不得**切到 `%APPDATA%\SuYan`，也不得把那份旧库合并进已有便携 `data\`。
4. **托管导入**：复制到软件目录的素材必须写入 `userData\library\images\`，元数据写入 `userData\library\library.json`；文件名使用 item `id` + 原始或安全推断扩展名。
5. **仅索引导入**：允许 `mediaStorage: { kind: "external", rootId, relativePath }` 记录用户目录中的外链素材；只保存相对路径和分类、标签、标题、提示词等元数据，绝不把原始像素复制进 `images\`，也不得保存未注册根目录的绝对路径。
6. **升级迁移**：正式包首次启动若本地 `data\` 尚无库数据，必须从旧版 `%APPDATA%\SuYan`（及历史名 `素言`、`PromptImageLibrary`）**自动复制迁移**到新 `data\`，之后只读写新路径，**不得**继续以 AppData 为正式存储。迁移实现见 `electron/main/app/appStoragePath.ts` 的 `prepareAppUserDataSync`，启动时在 `app.setPath("userData", …)` 之前完成。
**示例**：
```text
# 安装到 D 盘
D:\Apps\SuYan\data\library\library.json
D:\Apps\SuYan\data\library\images\018f4cc0-4fd2-7a0e-8e7a-63b7f99f0b12.png
D:\Apps\SuYan\logs\app.log

# 便携版
E:\便携软件\素言\data\library\...
E:\便携软件\素言\logs\app.log

# 开发 / 本地 package:win 迭代（与用户打开的便携包同一份数据）
<workspace>\release\win-unpacked\data\library\...
<workspace>\release\win-unpacked\logs\...
```
**违规特征**：正式包 `app.setPath("userData")` 指向 `%APPDATA%`；便携版数据写到 C 盘；把图片转为 base64 写进 `library.json`；external 保存未注册 root 的绝对路径；扫描外链目录时调用 `copyFile` 或 `writeImportMediaFile`；升级后仍读写旧 AppData 且无迁移。

### R3.2: 升级会清空 `data\` 是既定取舍，只做提醒不做拦截
**断言**：
1. **已确认的行为**：electron-builder 26.15.3 的 NSIS 卸载器对 `$INSTDIR` 执行 `RMDir /r`（`templates/nsis/uninstaller.nsh:187`），升级路径把 `$INSTDIR` 整体 `Rename` 进 `$PLUGINSDIR\old-install`（退出即删，`un.restoreFiles` 只在 rename 失败的回滚分支执行）。因此**安装版覆盖升级与卸载都会删除 `$INSTDIR\data\`**。便携版换目录解压则是旧 `data\` 留在旧目录、新目录从空开始。
2. **产品决策（不要"修回来"）**：优先保证"安装版和便携版都能直接覆盖升级"，**不**实现 `customRemoveFiles` 宏保留 `data\`，**不**把数据迁出软件目录。R3 第 1、2 条继续有效。
3. **必须提供的补偿**：升级提示可见时（`checkForUpdates` 返回 `update_available`），关于对话框必须显示备份提醒 + 「打开数据目录」按钮，引导用户把整个 `data\` 复制到软件目录之外。实现见 `electron/main/app/dataDirectory.ts`（`shell.openPath(app.getPath("userData"))`）与 `src/features/library/components/shell/AboutDialog.tsx`。
4. **提醒文案不得指向"导出分享包"**：`archiveStore` 的 ZIP 是分享格式而非备份——`randomUUID()` 重签 `id`、external 转 managed；虽通过 `analyzedLibraries` 携带所选作品对应的分类与标签库并保留原始时间，仍不含完整词库、view-settings / ai-settings / library-roots / 启动图库 / 画布参考图 / 代理设置。只能引导"复制整个 `data\` 文件夹"。
**示例**：
```text
# 升级前（用户手动）
D:\Apps\SuYan\data\  →  D:\备份\SuYan-data-0.2.10\
# 升级后（用户手动还原）
D:\备份\SuYan-data-0.2.10\  →  D:\Apps\SuYan\data\
```
**违规特征**：以"防数据丢失"为由新增 NSIS `customRemoveFiles` / `installer.nsh` 保留 `data\`；把 `userData` 改回 `app.getPath("userData")` 默认 AppData；备份提醒里让用户"导出分享包再导入"；更新提示中不给「打开数据目录」入口。

### R3.1: external 删除与压缩铁律
**断言**：删除 external 条目只能删除 `library.json` 索引和应用自有 `thumbnails/` 缓存，绝不 `unlink` 用户原文件。压缩、转码、格式替换只允许 managed 条目；external 默认跳过并在结果中明确提示，禁止写回原文件。用户需要压缩时，应先通过普通导入创建 managed 副本。

ZIP 导出是只读例外：必须经统一路径解析读取 external 源文件并把字节写入 ZIP，同时把包内条目标记为 managed，禁止把挂载根绝对路径或 external 引用带给接收方。缺失源文件必须明确报错，不得输出不完整分享包。

**违规特征**：external 删除路径落到挂载根；批量压缩/视频转码将 external 文件作为输出目标。

### R4: Zustand store 不得直接持久化文件
**断言**：`useLibraryStore` 只能管理内存状态和调用 `window.suyanApi`；不得在 store 中直接访问文件系统、LocalStorage 或 Electron API。
**示例**：
```ts
export const useLibraryStore = create<LibraryState>((set, get) => ({
  items: [],
  selectedItemId: null,
  load: async () => {
    const result = await window.suyanApi.readLibrary();
    if (result.ok) set({ items: result.data.items });
  },
  save: async () => {
    const library = buildLibraryFile(get().items);
    return window.suyanApi.saveLibrary(library);
  },
}));
```
**违规特征**：store 中出现 `localStorage.setItem`、`fs.writeFile`、`ipcRenderer.invoke` 或保存 base64 图片。

### R5: schema 变化必须提供迁移函数
**断言**：任何修改 `LibraryFile` 或 `LibraryItem` 字段的提交，必须同步新增 `W:\提示词\src\features\library\utils\migrateLibrary.ts` 中的迁移逻辑和 Vitest 单元测试。
**示例**：
```ts
export function migrateLibrary(input: unknown): LibraryFile {
  const file = parseLibraryFile(input);
  if (file.schemaVersion === 1) {
    return file;
  }
  throw new Error("Unsupported library schemaVersion");
}
```
**违规特征**：直接把 `schemaVersion` 从 `1` 改成 `2`，但没有旧数据迁移和测试。

### R6: 用户可见设置必须显式持久化
**断言**：任何会影响用户下次使用体验的设置、开关、下拉选项、AI 快捷选项或显示偏好，都必须写入正式数据目录下的本地 JSON 设置文件，并通过 `preload + IPC + 主进程 store` 持久化；不得只保存在 React 组件 state、Zustand 内存 state、URL、临时变量或构建产物中。

**示例**：
```text
data\library\ai-settings.json          # AI 模型、规则、快捷分析来源
data\library\view-settings.json        # 视图、排序、显示偏好
```

**违规特征**：用户选择“从效果图分析”后关闭、重启或重新打包又回到默认值；打包脚本试图用 `resources\app.asar` 中的默认配置覆盖用户 `data\`；新增 UI 设置没有对应的读写测试。

**验证要求**：新增或修改用户可见设置时，必须至少增加一条回归测试覆盖“保存到 JSON 后重新读取/公开设置仍保留”，若该设置位于正式包 `data\`，还必须确认 `pnpm package:win` 不覆盖现有数据。
