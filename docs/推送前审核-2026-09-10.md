## 本轮已处理的问题

### 1. [已修复] 恢复备份与测试输出仍可被提交

位置：[.gitignore](../.gitignore#L44)、[.gitignore](../.gitignore#L67)。

`git ls-files --others --exclude-standard` 返回 687 个文件，总计 1,206,644,955 字节。其中 `recovery-backups/` 有 258 个文件，`output/` 有 131 个，`.playwright-cli/` 有 30 个。备份中含真实 library.json、词库、撤销记录和原图；最大 ZIP 为 166,190,506 字节，超过 GitHub 普通 Git 单文件限制。

根因是 `/library.json`、`/library/` 仅排除根目录，未覆盖恢复备份目录。若直接 `git add .`，会同时造成个人数据泄漏和推送体积问题。当前未发现这些运行数据已经进入 Git 跟踪，不能把“可误提交”表述成“已泄漏”。

处理：已在 `.gitignore` 排除恢复备份、测试输出、Playwright 状态和账号运行数据；当前 `git ls-files --others --exclude-standard` 为 267 个文件，恢复备份、output 和 Playwright 状态均为 0。推送前仍需人工确认实际暂存清单，依赖组件 ZIP 继续使用独立 Release 资产。

### 2. [已修复] 旧账号刷新请求会覆盖或清除新账号会话

位置：[tokenManager.ts](../electron/main/account/tokenManager.ts#L22)、[tokenManager.ts](../electron/main/account/tokenManager.ts#L43)、[accountService.ts](../electron/main/account/accountService.ts#L887)。新增账号模块，HEAD 中没有对应文件。

成功返回路径：A 的过期令牌发起刷新 → clear/setPayload 切到 B → A 的请求返回。TokenManager 的 `.then` 无条件写入 A 的 payload；AccountService 在 await 后检查版本时，内存令牌已经被覆盖。隔离复现结果为“期望 B，实际 A”。

失败返回路径：A 发起刷新 → B 登录 → A 返回 ACCOUNT_REFRESH_FAILED。catch 没有检查原始 sessionVersion，就调用 clearLocalSession，清掉 B。隔离复现结果为“期望 B，实际 null”。

处理：TokenManager 已按会话代次隔离刷新结果，`clear`/`setPayload` 会使旧任务失效；成功、失败和 `finally` 均校验任务代次。AccountService 只允许当前会话的刷新失败清理该会话。回归已覆盖刷新成功/失败跨切换、退出后迟到响应和跨代次刷新锁。

### 3. [已修复] 昵称更新响应可把 A 的资料与 B 的令牌保存到一起

位置：[accountService.ts](../electron/main/account/accountService.ts#L311)，另需一并检查删除头像路径约第 360 行。

updateCurrentAccountProfile 在请求前取得 A 的凭据，但 await 后调用 `persistCurrentUser(user)` 时没有传入请求开始时的 sessionVersion。该函数默认取调用时的当前版本，因此 A 的迟到响应在 B 登录后仍被接受。

隔离复现：A 提交昵称更新 → B 登录 → A 响应返回。结果为 currentUser=A、token=B，持久化的 user 也为 A。选择自定义头像已有版本校验，但不能因此认为全部资料操作都受保护。

处理：资料更新已固定请求开始时的 uid、会话代次和令牌，并在异步返回后再次核对；保存时拒绝不同 uid，删除头像、绑定/解绑和登录完成路径复用同一会话约束。

### 4. [已修复] 系统加密不可用时，正式包也会将凭据退化为可逆 Base64

位置：[accountCrypto.ts](../electron/main/account/accountCrypto.ts#L13)、[aiSettingsStore.ts](../electron/main/ai/aiSettingsStore.ts#L162)、[promptAccountCrypto.ts](../electron/main/library/promptAccountCrypto.ts#L10)。

这些路径在 safeStorage 不可用或加密抛错时生成 `dev1:` + Base64，没有限制为开发模式。Base64 不是加密。使用虚构凭据、模拟正式包且 safeStorage 不可用时，已证明无需系统密钥即可读回 refresh token。现有 accountCrypto 测试反而把该降级视为预期行为。

处理：正式包加密失败时已停止敏感数据持久化并返回明确错误；开发环境的临时降级已显式限定。账号令牌、AI API Key、作品归属密码和相关备份均已覆盖。

### 6. [已修复] 本地收件服务没有在导入前拒绝外部网站来源

位置：[importReceiver.ts](../electron/main/library/importReceiver.ts#L103)、[importReceiver.ts](../electron/main/library/importReceiver.ts#L129)。新增模块。

不受信任的 Origin 只导致响应不写 Access-Control-Allow-Origin，仍继续解析 multipart 并执行 importImageBuffers。CORS 限制响应读取，不能作为阻止普通跨源表单 POST 写入的校验。

隔离服务以随机回环端口启动，磁盘导入完全模拟。发送 `Origin: https://untrusted.example` 的 multipart POST，结果 HTTP 200、ok=true、import 调用一次，ACAO=null。没有向真实 9477 服务写入测试数据。浏览器自身的私有网络保护可能额外限制部分调用，本次未声称所有浏览器都可直接利用。

处理：已在读取请求体前校验 Origin，外部和 `null` 来源返回 403，合法回环来源与无 Origin 的本地 ComfyUI/CLI 路径保持可用；已增加外部表单 POST 拒绝和正常回环导入回归测试。
