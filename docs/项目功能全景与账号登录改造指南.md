# 素言（SuYan）项目功能全景与账号登录改造指南

> 本文档供**接手实现账号登录功能的智能体**使用：前半部分是项目功能全景，后半部分是登录 + 导出携带用户信息（用户名/头像）的改造指引。
>
> ⚠️ **实施以 [账号登录实施总方案](./账号登录实施总方案.md) 为准**：本文档只提供项目全景与挂载点，具体架构、契约、错误码、验收标准与实施顺序见实施总方案。
>
> 任务目标：
> 1. 为项目增加账号登录功能，支持**邮箱注册**、**谷歌（Google）账号**、**Linux.do 网站账号**、**GitHub 账号**四种注册/登录渠道。未具备个人开放平台资质的社交 OAuth 渠道不纳入账号配置。
> 2. **已登录用户**在执行导出内容（图片导出、ZIP 分享包、灵感库 JSON 导出等）时，导出物要**携带用户名与头像**。

| 测试 | Vitest 4（`tests/unit/`），`pnpm test` |
| 包名 | suyan，appId `local.suyan`，Windows 用户模型 ID `local.suyan` |

### 进程模型

- **主进程** `electron/main/`：文件系统、剪贴板、网络、safeStorage 加密、Rust 扫描 Sidecar、本地收件服务、窗口与协议。
- **preload** `electron/preload/index.ts`：`contextBridge.exposeInMainWorld("suyanApi", …)` 暴露**白名单业务方法**（无通用 invoke/send/on）。`sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`。
- **渲染进程** `src/`：React 应用，**只能通过 `window.suyanApi` 调用桌面能力**，禁止直接 import electron/node:fs/ipcRenderer（规则 06 R1）。
- 入口：`src/main.tsx` → `src/app/App.tsx`（Profiler + Suspense + lazy 加载 LibraryView）→ `src/features/library/components/LibraryView.tsx`（唯一主界面，约 1 万行，含侧边栏导航与各视图）。

### IPC 模式（登录功能必须沿用的骨架）

1. `electron/shared/ipcChannels.ts`：`export const enum IpcChannelName { … }` 声明通道名。
2. `electron/main/ipc/registerIpcHandlers.ts`：`registerIpcHandlers()` 内用 `handleResult("channel-name", () => handler())` 注册；handler 返回值自动包装为 `{ ok: true, data } | { ok: false, error: { code, message } }`（错误用 `AppError`，见 `electron/main/ipc/errors.ts`）。
3. `electron/preload/index.ts`：为每个通道加一个命名方法 `xxx: () => invoke(IpcChannelName.Xxx, payload)`。
4. `src/types/suyanApi.ts`：`SuyanApi` 接口 + `IpcResult<T>` 类型同步声明（渲染层类型来源）。
5. 渲染层调用：`const result = await window.suyanApi.xxx(payload); if (result.ok) … else …`。

### 持久化

- 数据目录：安装版/便携版为软件目录 `data\`（库 `data\library\`），开发态为 `release\win-unpacked\data`；主进程启动时 `prepareAppUserDataSync` 决定 `app.setPath("userData", …)`，**不得**回退到 `%APPDATA%\SuYan`（那是旧库）。
- 全部为**本地 JSON 文件 + 图片目录**，无数据库：
  - `library/library.json`（素材库主数据）、`prompts.json`（灵感库）、`library-roots.json`（素材目录）、`view-settings.json`（视图/偏好/词库/主题）、`category-lexicon.json`、`tag-lexicon.json`、`ai-settings.json`、`proxy-settings.json`、`window-state.json`
  - `images/`（原图）、`thumbnails/`（缩略图）、`startup-gallery/`（启动图库）、`canvas-references/`（画布参考图）
- 路径工具：`electron/main/library/libraryPaths.ts`；JSON 原子写：`libraryJsonPersistence.ts`。
- **密钥加密**：API Key、账号密码等敏感值用 Electron `safeStorage` 加密（`encryptString(...).toString("base64")`），`isEncryptionAvailable() === false` 时退化为 `dev1:` 前缀的本地 base64（仅开发/受限环境）。参考实现：`electron/main/ai/aiSettingsStore.ts`、`electron/main/library/promptAccountCrypto.ts`。解密只在主进程内存中进行，绝不落盘明文。

### 其它主进程基础设施（登录功能会用到）

- `electron/main/app/updateChecker.ts`：GitHub Release 更新检查（`关于` 对话框）。
- `electron/main/app/externalUrlPolicy.ts`：`normalizeExternalUrl` 只放行 http/https（外部链接安全白名单）。
- `electron/main/network/proxySettingsStore.ts`：系统代理设置，启动时 `applyStoredProxySettings()` 应用；`electron/main/ai/remoteAiClient.ts` 的 AI 网络请求遵循代理。
- `electron/main/runtime/rustCoreRuntime.ts` + `rustFileOps.ts`：Rust Core Sidecar（大目录扫描/流式分页）。
- `electron/main/library/importReceiver.ts`：本地收件服务，仅监听 `127.0.0.1:9477`（GET /guli/suyan/health；POST /guli/suyan/import），供 ComfyUI 推送素材——**可作为 OAuth 本地回调端口的参考实现**。
- `electron/main/app/appStoragePath.ts`（便携数据目录）、`gpuCrashGuard.ts`、`performance/performanceMonitor.ts`、`window/windowStateStore.ts`、`appLogger.ts`（脱敏日志）。
- `electron/main/index.ts`：单实例锁、自定义协议 `app-image` / `app-thumbnail` / `app-startup`（Range 请求服务本地媒体）、外部链接处理（`setWindowOpenHandler` + `will-navigate` 拦 http/https 交给系统浏览器）、窗口控制 IPC。

## 3. 导出链路盘点（「导出携带用户名与头像」的挂载点）

> 需求：**已登录用户**导出内容时，导出物要**带上用户名以及头像**。
> 实现前需决策：图片导出是**打水印（用户名+头像合成到图上）**还是仅**携带元数据**；JSON/ZIP 是**嵌入作者信息字段**。以下列出全部导出链路与实现位置。

| # | 导出功能 | IPC 通道 | 主进程实现 | 说明 |
|---|---|---|---|---|
| 1 | 素材 ZIP 分享导出（多选/详情） | `ArchiveExportZip` | `electron/main/library/archiveStore.ts` + `archiveExportPolicy.ts` + `zipIntegrity.ts` | ZIP 根目录含 `data.json`（schemaVersion + items）+ `images/`；导入器拒绝缺 schemaVersion 的包。**建议在 data.json 中加 `author: { username, avatarUrl }` 字段**（兼容旧包：字段可选） |
| 2 | 单图导出（详情页/浏览） | `ImageExport` | `electron/main/library/imageFiles.ts` 的 `exportImageToLocal` | 把素材原图另存/复制到本地。**若要做图片水印，此处对 Buffer 做处理**（sharp 已用于压缩，可复用） |
| 3 | 灵感库 JSON 导出/导入 | `PromptExport` / `PromptImport` | `electron/main/library/promptStore.ts`（`exportPromptLibrary` / `importPromptLibrary`） | 导出 `{ schemaVersion, kind: "suyan-inspiration-library", exportedAt, entries, categories }`；导入时 `readPromptExchangePayload` 严格校验 |
| 4 | 日志导出 | `LogExport` | `electron/main/logExport.ts` | 脱敏日志文件导出 |
| 5 | AI 设置备份导出/导入 | `AiSettingsBackupExport` / `…Import` | `electron/main/ai/aiSettingsBackup*.ts` + `aiSettingsBackupCrypto.ts` | 设置备份（含加密密钥的处理） |
| 6 | 分类/标签词库导出/导入 | `LexiconExport` / `…Import` | `electron/main/library/lexiconFiles.ts` | 词库 JSON 文件 |
| 7 | 画布生成图入库 | — | `electron/main/library/generatedImageData.ts` | 生成结果写入素材库（属导入非导出） |

**头像来源注意**：项目已有 `utils/authorAvatarSources.ts`，但那是给**站点作者头像**（从提示词站点抓取）用的，与用户头像无关；用户头像应由登录体系提供（登录返回头像 URL / 本地头像文件）。

## 4. 登录功能改造指引

### 4.1 需求拆解

1. **四种渠道**：邮箱注册（账号密码体系）、Google OAuth、Linux.do OAuth/凭证、GitHub OAuth。未具备个人开放平台资质的社交 OAuth 渠道不提供个人账号配置。
   - 第三方登录由统一身份服务承接；**桌面 Electron 应用做 OAuth 的常见做法**：`setWindowOpenHandler` 弹系统浏览器授权，或内嵌 `BrowserView`/新窗口走授权页，回调用**自定义协议（如 `suyan://oauth/callback`）**或本地回环端口（参考 `importReceiver.ts` 的 127.0.0.1 服务）收 code。`externalUrlPolicy.normalizeExternalUrl` 只放行 http/https，自定义协议回调需新增白名单分支或单独通道。
2. **登录态与用户信息**：
   - 用户信息（uid、用户名、头像 URL/文件、渠道、token/refresh token）持久化到哪？建议跟随现有惯例：`data/library/` 下新增 `account.json`（非敏感字段）与加密字段（token 用 safeStorage，参考 `aiSettingsStore.ts` / `promptAccountCrypto.ts`），或按 `.codex/rules/08` 的 JSON 原子写方式。
   - 渲染层需要全局登录态（显示头像/用户名、控制导出行为）→ 建议扩展 `useLibraryStore`（zustand）或新增独立 store。
3. **导出携带用户信息**：见第 3 节挂载点。所有导出路径都在主进程，主进程持有登录态即可注入；渲染层在导出前确认「已登录 + 用户名/头像可用」。

### 4.2 必须遵守的既有约定

- **IPC**：新通道按第 1 节 IPC 模式四步走（channels → registerIpcHandlers + `handleResult` → preload 命名方法 → `suyanApi.ts` 类型），返回值一律 `IpcResult<T>`。
- **渲染层隔离**：登录 UI 只调 `window.suyanApi`；任何网络请求（token 刷新、用户信息拉取）放主进程，参考 `remoteAiClient.ts` 的代理处理。
- **加密**：token/密码用 safeStorage，明文不落盘、不打印日志（日志需脱敏，`appLogger.ts`）。
- **安全**：OAuth 回调 URL 校验（防 open redirect）、PKCE 优先；`setWindowOpenHandler` 已有外链拦截，新增回调协议时注意不要扩大可打开协议面。
- **版本**：`package.json` version 高于已发布版本（0.3.x 可连续升）。
- **测试**：新增纯函数/解析/序列化单测（vitest）；IPC 相关测试参考 `tests/unit/` 下现有 mock electron 的写法（`vi.mock("electron", …)`）。
- **完成验证**：`node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit`、`node node_modules/typescript/bin/tsc -p tsconfig.electron.json --noEmit`、`node node_modules/vitest/vitest.mjs run`，最后 `pnpm package:win` 并报告打包结果。
