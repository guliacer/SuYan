# 作品归属与账户加密备份

## 本地作品规则

- 登录期间新生成的图像记录账户 UID、昵称、头像。归属以生成请求开始时的账户为准；生成后切换账户再收录不会改归属。生成收据仅保存在主进程内存中，重启或超过 500 个保留结果后，失效结果可通过用户确认手动关联，不能按保存时账户自动认领。
- 登录期间新增的本地导入关联当前账户；已有网络作者、分享包作者或其他账户的资料保留。旧素材不会因登录或迁移而自动归属。ZIP 中无作者的旧资料保留无归属。
- 详情头像悬浮显示提示，点击后确认同步整组效果图；批量管理提供“同步作品”和“仅选未关联作品”。普通同步跳过已有作者的素材；强制覆盖先勾选提醒，再通过主进程第二次确认。确认期间换号会阻止提交。
- 同一账户由稳定 UID 判定，不按昵称、邮箱或登录渠道判定。不同 UID 的相同提示词不合组。
- 账户资料更新后，本机已经关联同一 UID 的作品更新昵称与头像。旧渲染快照不能写回旧头像；未关联作品及其他 UID 保持原样。作品头像使用独立的内容地址缓存，避免退出账户或移除账户头像破坏作品展示。
- “同步作品”更新本机作品资料，不上传素材或提示词，不是云同步。其他人的离线副本不能远程更新；之后重新导出的资料携带最新头像。

## 分享导入导出

ZIP 分享包逐条保留 `accountOwnerUid`、`authorName`、`authorAvatarUrl`、`authorUrl`。本机头像字节存入包内 `avatars/`，导入方重建自己的缓存；不会携带导出机器的本机绝对路径。包顶层 `author` 表示导出者，不能用它批量替换各作品原作者。

单张静态图导出为 PNG，通过 `suyan-work` iTXt 块携带提示词、账户 UID、昵称和头像。导入按文件内容识别，扩展名错误仍可恢复。视频、音频原文件导出保持原格式，完整作者资料用 ZIP 分享包携带。

画布未收录结果也经过主进程导出 PNG，使用生成收据中的账户归属；没有有效收据时保留无归属，不按导出时账户认领。已收录画布结果读取素材库最新作者资料后导出。

导出没有作者的作品时，用户可选择仅在导出副本署名当前账户或保留原信息；不自动认领本地旧作品。已有作者不能被导出者静默替换。署名属于可编辑元数据，不是数字签名或版权认证。

## AI 设置第三种导出方式

新增“账户验证加密备份（含密钥）”。该方式始终使用 AES-256-GCM，无明文开关，也不需要用户输入备份密码。原有普通导出、密码加密导出继续保留。

备份格式版本为 3，公开头部包含 `format`、`formatVersion`、`ownerUid`、`keyId`、`algorithm`、`exportedAt`、`iv`、`authTag`、`ciphertext`。账户 UID 和 keyId 不是解密密钥。附加认证数据按以下有序数组序列化为 UTF-8 JSON：

```json
["suyan-ai-settings",3,"<ownerUid>","<keyId>","<exportedAt>","aes-256-gcm"]
```

主进程联网验证同一账户后取回 32 字节随机密钥。密钥和明文只在主进程处理；renderer 只获得预览统计与十分钟有效的单次导入令牌。应用导入时再次联网验证，并在提交文件前核查账户没有变化。未登录、不同账户、密文被修改、服务不可用均拒绝导入。服务未适配时明确报错，不回退公开 UID 派生密钥、本机专用密钥或明文。

## Guli Identity 必须适配的接口

当前工作区完成客户端契约；以下服务端接口仍需 Guli Identity 项目实现并部署，尚未完成线上端到端验收。

| 操作 | 接口 | 请求 |
| --- | --- | --- |
| 创建备份密钥 | `POST /v1/account/backup-keys` | Bearer access token，JSON `{"purpose":"suyan-ai-settings"}` |
| 读取历史密钥 | `GET /v1/account/backup-keys/{keyId}` | Bearer access token，无请求体 |

两个接口成功均返回 HTTP 200（创建也允许 201）：

```json
{"data":{"subject":"<Guli统一账户sub>","keyId":"<16至128位字母数字下划线或连字符>","key":"<32字节随机密钥的标准base64，44字符>"}}
```

客户端把 `issuer + "#" + subject` 与当前 UID 比对，GET 还必须返回请求的同一 keyId。服务端不能相信请求文件中提供的 subject/UID，必须由已验证的 access token 获取主体。

安全与兼容要求：

1. 验证 token 签名、issuer、audience、有效期以及账户可用性，使用现有桌面客户端的受保护 API 权限；如要新增 scope，需同时协调授权端与客户端，不得假定客户端已请求新 scope。
2. 以密码学安全随机数产生 32 字节密钥和不可预测 keyId。不得从 UID、邮箱、密码或 token 派生密钥。
3. 保存 keyId、owner subject、purpose 与创建时间；密钥通过服务端密钥管理或独立部署主密钥加密存储。部署主密钥与密钥记录必须具备恢复备份，不能因版本升级、重新登录、换头像或关联渠道而重置。
4. GET 只向密钥所属 subject 返回明文密钥；跨账户查询统一拒绝，不能泄露其他账户是否存在。第三方登录渠道关联到同一 Guli subject 时可以恢复；不同 subject 即使昵称相同也拒绝。
5. HTTPS，无跨域重定向；响应 `Cache-Control: no-store`；访问日志、异常日志、网关、APM 与审计不得记录 token、密钥或响应正文。设置请求速率限制。
6. 保留历史 keyId 的读取能力，确保备份跨设备、换登录方式后仍能恢复。密钥撤销/账户删除后的备份不可恢复，应有明确产品说明。接口未实现时可返回 404/405/501，客户端显示升级提示。
7. 回归覆盖未登录 401、账户失效、跨账户 403/404、未知 keyId、非法 purpose/keyId、A 创建后重登读取、A 多登录方式读取、B 拒绝读取 A、部署恢复后读取旧备份，且检查日志无敏感信息。

## 给 Guli Identity 项目的修改提示词

> 请在 Guli Identity 当前项目中实现“素言 AI 设置账户验证加密备份”的密钥 API，并保持现有注册、邮箱验证、OAuth、设备验证码与用户资料接口兼容。先检查当前鉴权、统一 subject、持久化和部署方案，再实际修改并测试。新增 POST /v1/account/backup-keys，Bearer 鉴权，请求体 {"purpose":"suyan-ai-settings"}；新增 GET /v1/account/backup-keys/{keyId}，仅所属账户可读取。响应统一为 {"data":{"subject":"统一账户sub","keyId":"16至128位字母数字下划线或连字符","key":"32字节密码学安全随机密钥的标准base64"}}。subject 必须取自已验证 token，禁止相信客户端 UID。不要用 UID、邮箱或 token 派生密钥；密钥需加密持久化，主密钥与记录应可备份恢复，历史 keyId 跨设备与登录渠道关联后仍有效。接口必须 HTTPS、Cache-Control no-store，禁止缓存或记录密钥、token、响应正文。使用现有桌面客户端权限；若 scope 必须变化，给出精确客户端配置变更。完成未登录、跨账户、过期 token、关联渠道、旧备份恢复、日志脱敏测试，更新部署迁移文档，并明确是否已部署。与素言格式 v3 的 AES-256-GCM 联调：ownerUid = issuer + '#' + subject；AAD 为 UTF-8 JSON 数组 ["suyan-ai-settings",3,ownerUid,keyId,exportedAt,"aes-256-gcm"]。验收要求：账户 A 导出后在另一台设备登录 A 可导入；未登录或 B 无法导入；文件篡改、密钥服务不可用时拒绝，不提供不安全降级。
